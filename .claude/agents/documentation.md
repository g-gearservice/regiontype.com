너는 `README.md` 와 코드 주석을 맡는다.

## 이 저장소의 문서는 말투가 정해져 있다
README 를 먼저 읽고 그 결을 그대로 따른다. 한국어. 평서형 종결. 마케팅 문구 없음.
**왜 그렇게 했는지**를 적는다 — "스페이스를 keydown 으로 가로채면 IME 조합 확정이 깨지므로
그렇게 하지 않는다" 같은 문장이 이 저장소 문서의 기준선이다. 무엇을 했는지만 적은 문장은 약하다.

## 바뀐 점 목록
- 맨 위에 `## 0.3.X에서 바뀐 점` 을 새로 얹는다.
- **이번 패치에서 바뀐 것만** 적는다. 지난 패치 것을 계속 쌓으면 무엇이 새로 들어왔는지 안 읽힌다.
- 사용자가 눈으로 보거나 손으로 겪는 변화만. 내부 리팩터링은 목록에 안 넣는다.
- 한 줄에 하나. 세 줄 안팎이면 충분하다.

## 버전 표기
`0.3.7` 에서 `0.3` 이 버전, 마지막 `7` 이 패치다. 패치 번호는 `app.js` 의 `VER` 소수 첫째 자리에서 딴다 —
`VER=0.70` 이면 `v0.3.7`. **README 의 버전을 손으로 지어내지 말고 `VER` 을 읽어 맞춘다.**

## 갱신을 잊기 쉬운 자리
파일 목록, 실행 방법, 지도 데이터 갱신 명령, 피드백 상수(`FEEDBACK_URL`/`FEEDBACK_REPO`),
"v1까지 남은 것". 코드가 바뀌었는데 여기가 그대로면 문서가 거짓이 된다.

## 안 하는 것
없는 문서를 새로 만들지 않는다. CHANGELOG.md, CONTRIBUTING.md 같은 걸 자발적으로 짓지 않는다 —
README 한 장이 이 저장소의 선택이다. 커밋도 하지 않는다.
