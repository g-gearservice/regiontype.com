# PLAN — 새 소개 화면(/landing/)을 방문자 말로

> 일이 시작될 때 만들고, 마일스톤마다 고친다. 끝에 한 번 쓰는 문서가 아니다.
> 검사는 `?rt=1` · `node relay/test.mjs` 둘뿐이다. 러너를 새로 세우지 않는다.

## 할 일

v1.3.0 에서 새로 만든 소개 화면에 `landing/i18n.js`(옛 소개 화면용, main 에는 없음)를 붙여, 접속 지역과 브라우저 말이 맞는 방문자에게 그 말로 보인다.

## 까닭

새 소개 화면은 한국어뿐이다. 게임 화면은 26개 말을 받는데, 처음 보는 화면이 한국어로만 나오면 바깥 방문자는 거기서 돌아선다.

## 방법

- `landing/i18n.js` 는 옛 갈래(`claude/landing-i18n-ae0c3f`)에서 그대로 가져온다. 고르는 차례는 엄격하다 —
  설정의 말 → 계정에 고정된 말 → 중계기 `/where` 나라의 공용어가 브라우저 말 목록에도 있을 때만 → 그 밖은 한국어.
- 말은 `data/landing-i18n.json`. 옛 키 가운데 새 화면에 같은 문장이 있는 것(소개 판·스토리·플랜·문서 제목)은 번역을 그대로 쓰고, 새 문장만 새 키로 더한다.
- 구 이름은 게임과 같은 표(`data/kr-names.json` 로마자, ja·zh·uk·bg 는 제 글자)에서 옮겨 `gu.<구>` 키로 둔다.
- 염창동 한 줄 소개는 `data/kr-intro.<말>.json` 그대로다. 지어내지 않는다.
- 페이지 스크립트가 쓰는 말(지도 설명줄, 코스 차례, 쳐 보기 안내, 바뀐 것)은 `RT_LANDING.t` 로 꺼내고 `rt-landing-i18n` 때 다시 쓴다.
- 쳐 보기는 한국어가 아니면 그 말의 구 이름(대소문자·붙임표·'-gu' 무시)도 받는다.

## 마일스톤

검사가 통과하기 전에는 `[x]` 하지 않는다.

- [x] **M1: 키 달기** — 새 화면의 보이는 말에 모두 `data-i18n` | 검사: 브라우저에서 `RT_LANDING.set('en')` 뒤 한글이 남은 끝 요소 0
- [x] **M2: 26개 말 표** — `data/landing-i18n.json` 의 새 키가 26개 말 모두에 있음 | 검사: 키 수 비교 스크립트
- [x] **M3: 스크립트 말** — 설명줄·코스 차례·쳐 보기·바뀐 것이 고른 말로 | 검사: en·ja·ar 에서 화면 확인
